## 5. 发现的问题与风险

1. 真实 `/api/chat` 响应较慢，本次本地 `qwen3:8b` 流式回答耗时约 168.8 秒。检索和上下文构建通常在 1 秒左右，主要耗时在本地模型生成阶段。
2. 知识库中 `03-前端状态管理与数据流-第1-21题.md` 占 155/222 chunks，体量明显更大。部分泛化查询可能更容易被该文件吸走结果，但本次核心中文精准问题均能正确命中。
3. `rag=true` 在完全无关问题且无检索结果时仍返回 `enabled=false`，这是当前实现行为：强制 RAG 只是在检索失败时抛错，若检索成功但结果为空则不注入上下文。行为合理，但前端文案可避免理解成“必定注入”。

## 6. 建议

1. 保持当前向量库状态，无需重建索引。
2. 如果前端要展示“为什么引用这些内容”，可以直接使用 `/api/chat/context` 的 `results` 展示文件名、chunk、score。
3. 对本地模型响应慢的问题，可以在前端增强流式 loading、超时提示，或增加小模型/远端模型对比。
4. 后续可加一组固定 RAG 回归测试脚本，覆盖状态、架构、Agent、缓存、无关问题五类场景。

## 8. minScore 参数评估

补充测试时间：2026-06-25 10:44（Asia/Shanghai）  
测试接口：`GET /api/search`

- 相关问题会不会被更高阈值误杀。
